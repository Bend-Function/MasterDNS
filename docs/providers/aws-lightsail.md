# AWS Lightsail 旧静态 IP 清理恢复

2026-10-23 增补。适用于换址后的 `lightsail.static-ip.release`；不改变地址绑定、实例生命周期或额外云操作授权。

## 失败与恢复

清理失败后，先读取原静态 IP 的真实状态。AWS 返回 NotFound 时，任务记为已释放并继续收尾；历史 release operation 即使 Failed，也不能把已完成的删除永久卡住。

旧 IP 仍存在时核对原名称、ARN、地址及附着状态。资源一致且未附着，并且该次派发的所有 operation 都已结束、至少一个 Failed，才认定清理未生效并允许重试 ReleaseStaticIp。存在未完成 operation 时继续观察；ARN 变化、地址变化或重新附着时保留资源并显示错误。HTTP/SDK 正常响应缺少 staticIp 不等同于 NotFound。

重试沿用原资源和清理步骤，保留历史回执，新的派发记录新 operation ID。不会重新申请 IP、重放解绑/绑定或重新触发 DNS 切换。请求/观察异常与收敛超时使用换址策略的“失败自动重试上限”，默认 5 次（首次失败后最多额外 5 次），与云端换址阶段累计共享；重启不会清零。速率准入和更长的 Retry-After 仍有效。

## 控制台与操作

轮换列表与详情的 active 显示为“执行中”，清理错误显示为失败或重试中，详情保留资源错误及累计重试次数。达到上限后停止新清理写入，自动切换开关保留；已派发但结果未知的步骤继续只读确认。人工暂停/终止和当前授权仍有效。

已有 cleanup_failed 任务部署新 Worker 后可接续；若先前被人工终止，任务不会自动复活。部署须包含迁移 0034（来自失败恢复功能）、API/Web/Worker，无额外迁移或新环境变量。处理凭证/权限、额度或资源问题后可显式恢复原任务。

本地验证见[Lightsail 清理修复记录](../validation/2026-10-23-lightsail-cleanup-recovery.md)。Fake SDK 测试不等于真实 AWS 或生产环境验收。

## 终止旧任务后的域名重新分配

清理阶段被手动终止时，当前 IP 行可能继续保留，但该次发布已标记 `manual_terminated`。旧版恢复器仅补全缺失的地址行，因此分配池仍可能引用这条作废发布，使多个域名一起报 `Cloud publication is missing or superseded`，更新在本地被拒绝。

新版恢复器会对仍保留的当前地址创建更高的候选版本，重新收集外部健康证据；通过成功阈值与 AWS 只读清单核对后，创建独立发布及新的 DNS 操作。分配池在此之前排除已作废发布，强制调度也不能绕过。旧任务不复活，旧资源的保留状态和被手动关闭的轮换开关不变；活动任务、暂停任务和未决云操作继续受到原有隔离。没有有效健康策略或证据不足时继续等待。

无需删除节点、重新申请 IP 或反复重试旧 Operation。升级后查看最新地址检查和新操作，旧失败历史不会改写为成功。此路径无新增迁移，相关 Lightsail 本地回归见[作废发布恢复验证](../validation/2026-10-23-dns-validation-diagnostics.md)。
