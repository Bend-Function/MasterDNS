# AWS Lightsail 故障后的同步重置恢复

2026-10-24 起，已开启 IP 自动轮换的 Lightsail 节点在云切换失败、云端等待超时、DNS 发布或旧资源清理失败后，自动执行与实例详情按钮相同的“同步云端并重置本地状态”流程。EC2 也支持此流程。

## 自动恢复流程

1. 锁定实例及地址上下文，核对账号、管理/地址族授权、策略版本和物理租约。
2. 读取 AWS 实际身份与实例清单。云调用共享最多 `min(cloudWaitSeconds, 30)` 秒预算；失败/超时只保存错误及重试时间，不清本地状态，也不继续重放旧步骤。
3. 读取成功后结束旧任务，作废旧发布和排队 DNS 操作，放弃旧待定步骤并清除本地步骤阻塞。旧回执、审计和未释放资源保留。
4. 使用真实 IP 重建地址版本，清除旧健康证据，保持重置前自动轮换开关开启。旧任务显示“已同步重置”。
5. 实际 IP 重新达到外部健康阈值后发布；仍确认故障则自动建立新任务。新任务使用新清单、新版本、新步骤，并继承已用恢复次数。

默认最多自动同步重置 5 次，沿用“失败自动重试上限”（0–20）。同步尝试开始前计数，同步失败也占一次；新任务、进程重启或 Redis 重投不会刷新预算。通过独立健康发布或正常完成任务后结束恢复链。耗尽后停止自动重置，保留开关和原因；处理实际故障后可显式点击“同步云端并重置本地状态”重新开始。仅切换自动开关不会解除旧任务的版本隔离或刷新预算。

用户主动暂停/终止、关闭开关、授权或配置变更、实例生命周期操作及其他地址族已执行/被暂停的任务会阻止自动重置。尚无 Attempt 的排队健康任务可随同实例重置替代，避免 IPv4/IPv6 互相等锁。限流等待不等同于任务卡死；单纯探针不足不会强行换址或发布。

同步重置只调整本地接管状态，不能撤回已经发送给 AWS 的请求；迟到旧回执不能覆盖新状态，云端之后发生的变化仍由新清单与探测确认。旧静态 IP/计费资源不会因为重置被标记成已删除，也不会重新自动释放，需在资源详情或云清单中核对保留项。

## 手动任务与原释放适配器

未开启自动轮换的手动/定时任务继续使用原有步骤恢复。原静态 IP 返回 NotFound 时可确认已释放，不受历史 Failed operation 阻挡；仍存在时核对原名称、ARN、IP 与附着状态。该次派发的全部 operation 结束且至少一个 Failed，才可认定未生效并重试原 ReleaseStaticIp。身份变化或归属不明确仍需保留资源。

这部分原始适配器行为的历史验证见 [2026-10-23 Lightsail 清理记录](../validation/2026-10-23-lightsail-cleanup-recovery.md)。该旧记录不代表新版自动同步重置的生产验收。

## 升级与验证

先备份、停止旧 API/Worker，执行迁移 `0035_rotation_reset_recovery`，再同步升级 API/Worker/Web。无需新环境变量；旧 Slot 从 0 开始新的同步重置预算，旧策略开关、资源及审计保留。当前验证范围见 [2026-10-24 同步重置回归](../validation/2026-10-24-cloud-reset-recovery.md)，本地替身测试不等于真实 AWS 写入或生产部署验收。

手动终止后仍存在 current 地址行但 Publication 已作废的独立复测恢复继续有效；旧任务保持终止，重新验证后生成新发布。其历史修复见[作废发布恢复记录](../validation/2026-10-23-dns-validation-diagnostics.md)。
