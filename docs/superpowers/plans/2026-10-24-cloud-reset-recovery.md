# AWS 自动同步重置恢复实施计划

用户明确指定失败恢复流程：同步实际云状态 → 重置本地状态 → 恢复 IP 自动轮换；默认最多 5 次，不能继续重放卡住的同一步。

- [x] 将现有 AWS 手动重置的持久事务提取为共享函数，API 继续使用同一身份、授权及清单验证。
- [x] Worker 为已启用自动轮换的 AWS 故障任务接入同步重置；有界等待、物理租约、失败预算、手动暂停/关闭、授权变更继续有效。
- [x] Slot 持久保存累计恢复次数，新的故障任务继承恢复次数；健康验证与发布成功后结束恢复链。旧任务终止、旧资源保留、旧回执只记历史。
- [x] 通过隔离 DB/Redis 测试同步失败不清状态、重启/重复执行、连续五次失败、最新地址重建、开关和手动操作隔离；运行相关 API/Worker/Web 回归及构建、类型、Lint。
- [x] 同步架构/数据模型/部署/厂商文档和验证记录，审查后提交并推送 master。

本次范围是现有手动重置支持的 AWS EC2/Lightsail。不会扩展 Azure/Linode 的重置语义，也不会直接修改生产云资源。自动重置只恢复已启用的故障自动轮换，不能覆盖用户主动暂停、终止、关闭或授权撤销。共享重置保留审计、计费资源记录与旧操作历史；实际云端可能存在的迟到副作用由后续清单和健康验证观察。
