# Linode temporary-instance IPv4 swap

Add an opt-in strategy inspired by https://www.laozuo.org/15773.html. Keep additional IPv4 allocation as the default. The current API supports a same-region two-way assignment at `POST /networking/ips/assign`; creating an instance supplies its standard IPv4 and incurs instance charges. No real cloud writes are part of development verification.

Policy fields: `linodeIpv4Strategy: "additional_ipv4" | "instance_swap"` (default additional_ipv4), `linodeSwapPlan: string` (default g6-nanode-1), `linodeAllowTemporaryInstance: boolean` (default false). The explicit grant covers creating and deleting only the temporary instance belonging to this attempt. Existing management, IPv4, stop/start, scope, identity, concurrency, revision, and rate-limit checks remain mandatory. Existing restart mode remains orthogonal.

The durable swap plan is `linode.swap.allocate`, `linode.ipv4.swap`, then the existing reboot or stop/start steps. Create an empty offline temporary instance in the original region. Save the returned instance identity and ownership proof; never repeat an uncertain create. Swap both public IPv4 addresses in a single API call. Read back both assignments before power operations and publication. Preserve the original instance and its disks. Reserved/shared addresses and unsupported topology fail closed.

Every receipt carries `after.temporaryInstance` with `{ id, label, created, region, attemptId, targetInstanceId, originalAddress, candidateAddress, type, accountId, externalAccountId }`; candidateAddress can be absent until allocation observation. Observed swap and power receipts also carry `after.swapVerified: true`. Missing creation receipts require operator resolution; inventory differences alone cannot authorize adoption or deletion.

Cleanup deletes the exact temporary instance holding the replaced address after DNS publication and the existing TTL grace. `linode.swap.delete` requires a saved applied swap receipt, current temporary-instance authorization, matching label/tag/creation/region/type/account identity, an offline empty helper, exact old-IP ownership, and a live replacement on the original instance. It must never delete the original instance. Resource aliases prefer the applied swap's original resource, preventing a prior candidate receipt from selecting the wrong helper across multiple attempts. A helper's physical identity is reserved while the incident owns it. Pause/termination retains paid resources visibly for operator review; uncertain writes are observed, never blindly replayed.

Expose strategy, temporary plan ID, explicit creation/cleanup authorization and cost/outage copy in Linode policy settings. Manual confirmation must use the saved policy even from instance details. Show retained temporary IDs in task details. Tests cover allocation loss, partial swap, authorization revocation, original-instance protection, both power modes, retries, and cleanup.
