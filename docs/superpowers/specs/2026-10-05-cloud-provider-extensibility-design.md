# 云厂商扩展边界整理

## 目标与范围

基于用户确认的四项方案，集中厂商注册、拆分能力接口、将换址规划/资源身份/清理差异纳入厂商扩展入口，并补可复用契约测试。起点为 `7f1a239`，分支 `codex/cloud-provider-extensibility`。现有 AWS EC2/Lightsail、Azure VM、Linode 的可用能力、错误码、授权要求和持久任务格式保持兼容。

不新增云厂商，不执行真实云操作，不迁移已有任务/数据库结构，不引入动态加载第三方代码。数据库 enum 保持显式 schema 和 SQL 迁移；新厂商仍需要凭证/能力实现及验收。

## 边界设计

1. **浏览器安全目录（contracts）**：厂商/服务标识、对应关系、名称、区域规则/示例、凭证 schema 与凭证种类归属集中定义。API 与 Web 复用，不能把服务端 SDK 或代理凭证明文带进前端包。已部署的凭证 discriminator 和 API 字段保持不变。
2. **服务端扩展注册（cloud-providers）**：每项服务注册适配器创建、静态能力判断、换址计划和清理计划。现有公共入口保留兼容委托，具体厂商实现不反向依赖汇总注册表，避免循环导入。
3. **按能力分接口**：清单发现作为最小能力，换址执行/观察、实例生命周期、月流量、空闲地址独立描述。只读适配器可独立实现；消费者在执行前显式校验能力，缺失能力返回稳定的 unsupported 错误。不能通过填充空壳变更方法假装支持。
4. **领域与厂商边界**：通用 Worker 保留事务、租约、版本、预算、外部探测与 DNS 发布。厂商资源身份、地址角色、换址步骤规划/清理判定通过命名明确的服务扩展策略调用。依赖数据库的 Linode 临时实例记录与删除保护保留在独立持久扩展中，不塞入纯适配器接口。
5. **契约验收**：可复用的测试入口验证清单归一化、身份隔离、能力缺失、计划派发与观察/恢复约定；现有厂商专属 fake HTTP/SDK 测试继续负责丢失响应、重启、权限、配额和清理。新增厂商不应只修改测试中的名字列表就算通过。

## 兼容与安全约束

- Node.js 22+、pnpm 11；TypeScript 严格类型，后端相对导入保留 `.js`。
- 保留授权、资源归属和模糊结果保护；接口重构不能扩大可执行范围。
- 不修改 CloudStep action/arguments、凭证 kind、现有 API payload 与数据库 enum 值，已有待执行任务可继续恢复。
- Browser/API 表单验证共享，但运行时代理注入与账号凭证输入校验仍有不同边界。
- Linode 删除临时实例的库存清理及监控/业务引用保护必须回归。

## 验收

- 注册目录覆盖现有全部服务，未知标识和跨厂商凭证仍拒绝。
- 新的只读适配器契约无须实现换址方法；错误能力不会被执行。
- 主流程不再重复维护厂商支持列表和换址规划 dispatch。
- 现有厂商的实例清单、手动/周期/健康换址、恢复、发布、清理测试保持通过。
- API/Web 凭证校验与显示兼容；前端构建不得依赖 server-only 包。
- 更新架构和新增厂商指南，明确扩展点、测试入口及剩余显式迁移工作。
