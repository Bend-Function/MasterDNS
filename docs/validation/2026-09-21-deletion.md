# 删除逻辑检查（2026-09-21）

## 已复现并修复

- 空 Pool 残留同步标记为已删除的托管 DNS 记录时，删除 Pool 触发外键 `SET NULL`，违反 `dns_records_managed_pool` 约束。删除前在同一事务中释放历史记录的托管关联，保留记录内容和删除时间。
- Pool 仍关联活跃 DNS 记录时，返回明确的 409 冲突，不再直接触发数据库约束异常。
- 节点、健康检查先删除后独立记录策略历史，审计失败可能导致接口报错但资源已删除。现与策略版本、审计写入保持同一事务。
- 节点引用检查在事务外执行，可能漏掉并发新增的绑定。现先获取 Pool advisory lock、Pool 行锁及节点行锁，再检查引用并删除。健康检查删除采用相同的 Pool 优先锁顺序。

## 删除规则

| 资源 | 条件与效果 |
| --- | --- |
| Pool | 必须没有域名绑定及活跃的关联 DNS 记录；清理已删除记录的托管关联后删除 Pool。剩余节点及 Pool 从属配置按外键级联清理。 |
| 节点 | 没有 desired/applied 分配且不是绑定的原始节点；清理非活跃分配，级联清理地址、DDNS 凭据及节点检查。 |
| 域名绑定 | 未发布且没有执行中或结果不确定的 DNS 写入时可直接删除；已发布则排队删除云端 DNS，成功后清理绑定。 |
| 健康检查 | 校验检查属于当前 Pool；删除及策略历史、审计同时提交。Cloud 槽位级检查不通过此接口删除。 |
| 普通 DNS 记录 | 非托管记录通过异步操作删除云端记录并保留历史；托管记录必须走 Pool 绑定流程。 |
| 通知渠道 | 渠道及关联按外键清理，审计同事务提交。取消 Pool 关联也与审计保持同一事务。 |
