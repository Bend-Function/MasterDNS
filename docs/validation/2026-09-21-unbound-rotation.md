# 未绑定域名的健康轮换恢复 — 2026-09-21

## 故障与修复

健康轮换已经在云端换址并验证候选 IP 后，旧发布逻辑仍要求存在 DNS 端点关联。没有关联时抛出 `publication_has_no_links`，协调器将其记录为 `rotation_runtime_failed` 并暂停在 `publish`。候选没有提升为当前地址，绑定页面因此继续显示云端已经不存在的旧 IP。

修复允许持有有效轮换事件的已验证候选在没有 DNS 关联时完成发布；没有事件的初始候选仍需要关联。授权、地址版本、外部健康证据和云端实时归属检查继续生效。

发布前健康证据不足或过期时等待同一候选的复测，包括云端读取期间证据过期的情况。暂停事件不会因此自动恢复。已经发布的事件继续观察 DNS 状态，手动换址保留原有健康检查规则。

## 已暂停任务的恢复

1. 在 Docker Compose 部署目录执行 `bash update.sh`，等待升级成功。
2. 保留原任务、旧地址和候选地址。如果需要释放用户原有 AWS 地址，在恢复之前打开该实例的“允许释放用户原有旧地址”开关。
3. 打开原来暂停在 `publish` 的轮换详情，点击“恢复执行”。不要创建另一条手动换址任务。当前健康轮换恢复接口会创建预算段，但继续发布仍保留原候选和原尝试，不重新分配 IP。
4. 外部 Agent 的同一候选复测满足成功门槛、且云端归属检查通过后，候选成为当前地址。刷新 DNS 绑定页面再选择它。
5. 发布完成后才进入清理。没有关联 DNS 时仍至少等待 60 秒；有 DNS 时还需等待发布验证与旧 TTL。释放还取决于资源归属、引用和授权检查。发布完成后才开启释放授权，不会自动回填已经标记为 `retained` 的历史资源。

这次修复没有数据库迁移，不改写生产事件，也没有执行真实 AWS 或 DNS 操作。其他原因导致的暂停仍需按实际错误诊断。

## 验证

- 先在隔离 PostgreSQL 中重现：IPv4/IPv6 无关联健康发布、恢复后证据过期、读取期间证据过期，四项回归均失败于旧代码。
- 修复后轮换模块全部 107 项测试通过，覆盖发布、清理、租约、恢复、手动换址，以及原尝试和云写入次数保持不变。
