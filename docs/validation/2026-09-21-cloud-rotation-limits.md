# 换 IP 限制策略

## 使用与默认值

在「云计算账号 → 换址限制」查看并修改比例，默认 80%，可设 1–100 的整数。AWS 账号分别配置 EC2 与 Lightsail。相同远端云账号、相同服务的多个本地账号共用预算，生效比例取它们的最低值；未配置的账号视为 80%。设置不会清零已有使用记录。

| 服务 | 默认生效值（80%） | 口径 |
| --- | --- | --- |
| Lightsail | 单变更接口突发 1、补充 0.8 次/秒；静态 IP 共用 40 次/滚动小时、400 次/滚动 24 小时 | 小时/每日规则跨区域共享，采用官方保证的最低 50/500 基准，不依据可能过期或不完整的实例清单放大预算 |
| EC2 | 普通换址接口突发 40、补充 4 次/秒；分配 IPv6 和修改网卡属性突发 80、补充 4 次/秒 | 每个接口、每个区域独立计数 |
| Azure VM | ARM 写入/删除分别突发 160、补充 8 次/秒；网络写入和删除合计 800 次/滚动 5 分钟 | 按远端订阅和区域；免费/试用订阅实际限额可能更低 |
| Linode | 合计 1,280 次/滚动分钟 | 将换址变更按远端账号聚合，严格于厂商按用户/操作的普通 1,600 次/分钟基准 |

整数请求不能拆分，令牌桶最小容量保留 1，补充速率仍按比例缩小。这里限制的是换址写操作，不是“换址次数”：一次换址可能包含多个 API 操作，清理也计数。现有失败尝试上限、最小换址间隔、管理授权继续生效。

Lightsail 申请/解绑/绑定之前，为未派发的后续静态 IP 步骤预留预算，防止其他任务抢占后续绑定额度。预留在暂停期间保留，以便安全恢复；任务完成、换尝试或放弃后不再占用。低比例连一次完整换址都容纳不下时，会明确暂停并提示提高比例，不无限轮询。已预留的完成步骤不因后续降低比例而被新预算阻挡。

Lightsail 清理 Release 仍计入动态窗口，但与 AWS 规则一致，动态窗口满时不阻止释放；接口速率和已观测到的云端共享冷却仍适用。

## 等待与安全恢复

达到本地预算后，任务显示“等待换址额度”和下次可重试时间。拒绝发生在步骤标记为已派发、扣失败尝试次数之前；不会发出该步骤的云写请求。预算和等待时间保存在 PostgreSQL 中，多 Worker、重启、替换凭证或重复添加同一云账号不能绕过。

真实云端返回限流时，同一账号/服务进入共享冷却，至少等待 60 秒，重复限流有界指数增长至 1 小时，并尊重更长的 Retry-After（最高记录 24 小时）。清理任务处于等待，不会把限流标成清理失败。

已经派发但结果不确定的请求继续走原有观察路径，不重新执行、不再次扣 API 预算。API 预算按持久派发意图保守记账，每个现有步骤最多执行一次变更；即使厂商拒绝、网络超时或远端已满足条件而没有实际变更，也不会返还这次 API 预算。

## 范围

只统计本版本启用后经过 MasterDNS Worker 的换址/清理派发，历史调用和其他程序、控制台的调用不自动导入；该限制不覆盖普通只读查询。20% 余量不能保证云端绝不返回限流。小时/每日均为滚动窗口，不在整点或午夜清零。

## 升级

新增数据库迁移 `0023_cloud_rotation_limits`，包含策略、预算、预留三张表。部署时先迁移再启动新 API/Worker；已有账号无需手动创建策略，自动采用 80%。常规 Docker Compose 部署沿用 `bash update.sh`。Go Agent 协议未变，无需更新 Agent。本次未执行部署或真实云端变更。
