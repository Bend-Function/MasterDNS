# 运行时缺陷与 Linode 临时实例清理验证

日期：2026-10-05。修复分支：`codex/runtime-fixes-linode-cleanup`，起点 `2b5f746`。

## 行为变更

- DDNS 候选和普通地址调度共用检查配置选择规则，尊重地址族策略明确选择的 Pool 配置。外部/混合模式由探测轮次推进，不再排队无效的本地候选检查。
- Linode 临时实例授权撤销按单资源准入拒绝处理；即使新事件准入出现意外数据库异常，已有到期换址事件仍会排队，异常继续交给日志处理。
- 前端初始加载、手动刷新和 SSE 刷新共用请求序号；旧请求、旧路径及卸载后的响应不能覆盖新状态。
- 确认 Linode 换址临时实例删除后，清理无业务引用的实例、网卡、地址和槽位库存，并从临时实例展示中移除。成功同步依据持久删除回执补清历史残留，并防止较早开始的扫描重新加入已删除实例。
- 清理比对账号、区域、远端 ID、名称和创建时间；仍在清理、失败扫描、新创建身份或已有管理/绑定/监控/操作引用的对象不会被误删。换址执行及审计历史继续保留。

## 验证证据

测试先确认旧实现失败，再运行修复后的回归；数据库使用专门的临时 PostgreSQL，队列使用本机独立 Redis，各测试创建独立数据库/队列。云侧只使用测试适配器，不连接真实云账号。

| 检查 | 结果 |
| --- | --- |
| `pnpm test` | 141 个测试文件、1,582 项通过 |
| API `ddns-local-health` 与 `ddns-external-health` | 2 个文件、9 项通过；覆盖真实数据库、Redis 与候选提升/故障转移 |
| Worker 同步与清理回归 | 2 个文件、91 项通过；含监控引用保护 |
| Web 请求顺序与预览回归 | 13 项通过，使用真实 React hook 与 happy-dom，网络边界由受控响应替代 |
| `pnpm typecheck` / `pnpm lint` | 通过 |
| `pnpm build` | 共享包、API、Worker 和 Next.js 默认生产构建通过 |
| 独立代码复核 | 一处监控引用保护遗漏已补回归并修复，复核无剩余发现 |

最终补充了同步清理的库存 ID 过滤，避免每次扫描对已经移除的历史临时实例逐一查询。该优化后单独重跑同步测试和 Worker 编译；完整套件与生产构建的记录对应此前同一修复版本，不声称对每次后续小改重复执行全套检查。

## 交付影响与边界

无数据库迁移、无新增运行环境变量。Web 仅新增开发测试依赖 `happy-dom`，锁文件固定版本。旧临时实例的自动补清需要账号启用、区域在扫描范围内、已有匹配且确认成功的删除回执；不能只凭名称前缀推断其已删除或属于系统。

未执行真实 Linode 建机/换址/删除、生产部署或浏览器视觉验收；测试通过不代表这些环境验收已完成。
