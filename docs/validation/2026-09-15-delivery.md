# 多云轮换与外部探测交付验证

日期：2026-09-15。平台在 `codex/multicloud-ip-rotation`，独立 Go Agent 在 `codex/external-health-agent`。本次只完成本地开发和验证；没有推送、合入 master、部署、发布 Agent 或操作真实 AWS/DNS。

## 功能范围

- 延伸现有平台：多云适配接口，首期接入 AWS EC2 / Lightsail，按账号与区域同步清单，实例默认未授权，用户显式选择可管理实例。
- DNS 的 A / AAAA 记录绑定具体地址槽，区分 IPv4 / IPv6；不能轮换的地址仍可绑定和监测，界面显示能力限制。
- 独立 Go Agent 通过 HTTPS 拉取任务并上报 TCP / HTTP(S) 结果；支持探测组、固定成员投票、连续阈值、探测不足状态、Token 安装与吊销。
- IPv4 / IPv6 自动轮换分别开关；尝试预算、间隔和窗口可配置。持久化云步骤、预算和远端观察，中断后恢复原尝试；远端结果不明时先观察。
- 候选地址通过外部复测后才发布 DNS；支持多个绑定、部分发布重试、备用节点、旧 TTL 宽限期与受限清理。初次地址验证和发布不要求开启自动轮换。
- 控制台包含云账号、实例与授权、探测点与组、健康策略、轮换事件与步骤、地址实际值/候选值/已发布值，以及独立的通知分类。

GCP、Azure、Vultr 仅保留扩展接口，尚未实现对应适配器。`allowStop` 保留为独立授权项；本期使用已实现的直接换址 API，没有未经验证的 stop/start 兜底。

平台命令使用 `pnpm_config_verify_deps_before_run=false`，用于本机 pnpm 包装器与已安装依赖版本差异。新增已声明的 `tsx` 依赖在缓存中存在，合入后补齐了本机忽略目录中的依赖链接；没有修改依赖包内容。

最终组合命令是 `pnpm test:probe-integration`，显式提供独立构建的 Linux arm64 Agent 路径和隔离 PostgreSQL 地址。它验证真实 HTTPS 注册/租约/结果、IPv4/IPv6 TCP 和证书校验 HTTPS、过期或错误版本结果拒绝，以及三轮失败→一次云适配器换址→三轮成功→实际 DNS Worker 发布。模拟远端的状态由父进程保留，5 个故障点实际终止子进程：分配后、关联后、部分 DNS 成功后、清理前、释放生效但回执未保存时。

断言同时检查原尝试和预算、成功 DNS 步骤不重放、只补缺失写入、所有释放请求的目标及当前地址仍附着。旧 DNS TTL 固定为 120 秒、新 TTL 为 60 秒，独立断言并实际等待 180 秒清理宽限期；同时验证自动轮换关闭时首次发布、恢复同地址后的故障向 Pool 传播及已验证备用节点切换。空库与已有数据的 0018→0019 迁移通过，最终清理了本次拥有的容器、网络、数据库和临时文件。

不同检查点的结果分别记录，未将早期完整套件描述为在后来每个提交上重复执行。运行步骤与边界见 [完整闭环验收](multicloud-ip-rotation.md) 和 [Agent 协议联调](probe-binary-integration.md)。

## 验证边界

- AWS 控制平面、DNS 写入和故障恢复采用隔离测试及生产适配器的模拟远端。真实 AWS IPv4/IPv6 换址、权限、配额和最终网络可达性尚未验收。运行真实验收的方法见 [AWS 控制平面验收](aws-control-plane.md)。
- Agent 的 Windows 原生运行、原生 Linux systemd 安装验收由 CI 定义，本机未执行；跨平台编译不等于原生验收。
- 前期云管理页面已进行桌面和移动预览；最终浏览器工具返回无可用浏览器及授权不可用，未完成本次刷新后的整套视觉验收。生产构建和页面逻辑测试已通过。
- 没有选定或发布 Agent 正式版本。平台可以在 `NEXT_PUBLIC_PROBE_AGENT_VERSION` 未配置时构建部署；实际安装前需配置已发布的固定版本。
- 数据库回退需要备份恢复；回退代码或数据库不能撤销已执行的云端操作。

## 本次实现中的取舍

以下保留本次开发过程中的全部 Ruling 记录；这些取舍不增加云端授权范围。

1. 使用用户已批准的两个新分支；如隔离不足，后续可迁移至额外 worktree。
2. 删除协议哈希清单，使用行为契约测试；代价是通过测试发现语义差异，而不比较文件哈希。
3. 保留有用途的认证 Token 哈希及一次发布产物完整性校验；如需进一步简化，应重新评估其安全作用。
4. 每个工作目录只保留一个实现写入者，允许评审和准备工作重叠；代价是部分任务吞吐较低。
5. 明确拒绝 IPv4-mapped IPv6；调用方需要提交原生 IPv4。
6. P1 契约冻结后，平台和 Agent 在不同仓库并行；接口偏差由契约测试和联调发现。
7. 普通 endpoint 编辑不转换云来源，必须走显式绑定生命周期；代价是转换多一步操作。
8. P2 阶段暂时拒绝云快照恢复，由 P10 补充引用实际 slot 并重新探测的恢复；阶段中能力暂不可用，最终已补齐。
9. P6/P8 使用不同临时 worktree 并行；代价是需在合入时验证接口。
10. 不构造未经验证的 AWS stop/start 兜底；不支持的配置需要另行实现和验证相应方法。
11. P9 纯状态机与数据库/Worker/API 分工，在独立 worktree 完成；代价是需验证两部分集成。
12. P10 同时负责无轮换事件的初次验证发布；否则自动轮换关闭时首次绑定无法发布，且不能为此伪造尝试预算。
13. Agent 发布配置使用可选的固定版本和可信 GitHub 来源；代价是首期不支持私有下载镜像。
14. Agent 使用用户批准的新分支；如隔离不足，后续可增加 worktree。
15. Agent 协议 fixture 使用行为验证而非哈希清单；只检测测试覆盖的语义差异。
16. Go 工具链安装到临时目录，语言基线保持 Go 1.26；临时目录清理后需要重新安装工具链。
17. Agent A7 打包在独立 worktree 与 A6 评审并行，只合入通过评审的源码；代价是最终需验证打包与源码一致，且本次未执行生产安装或发布。
