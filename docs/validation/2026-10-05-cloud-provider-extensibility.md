日期：2026-10-05。分支：`codex/cloud-provider-extensibility`，起点 `7f1a239`。

## 最终结构

- 浏览器安全目录统一 provider/service、区域、名称、凭证种类、严格输入校验和触发支持声明。API/Web 复用，凭证草稿采用通用 kind 选择。
- 服务端以 `CloudServiceRegistry` 注册工厂、能力、规划和纯工作流策略。原工厂/规划函数兼容委托，具体适配器不反向依赖注册表。
- 最小清单、换址、生命周期、流量和空闲地址能力独立；只读注册无须变更占位方法。声明换址必须提供 workflow，Worker 也在新派发前检查。
- AWS 地址角色、Azure 分配身份、发布与清理规则使用集中策略。数据库相关 Linode 临时实例证据、租约及清理留在持久扩展。
- 持久步骤 action/arguments、凭证 kind、数据库枚举值和已有授权范围保持兼容。

## 评审修正

- 契约测试最初只能验证具备换址的厂商，补充同一 suite 的只读注册和真实观察/恢复场景后复核通过。
- 注册类型和运行时校验要求 rotation 对应 workflow，避免云操作后才发现无法发布候选；执行器新派发前也检查，已有派发的观察保持可恢复。
- 清理执行器在发出副作用前要求详细观察接口，避免删除后缺少恢复能力。
- Web 手动换址入口复用共享支持声明；通过浏览器安全 `/cloud` 子入口导入，避免 contracts 根入口中的 Node 模块进入客户端。

完整套件、typecheck 和 lint 记录对应最后浏览器入口修正前/同期的执行。入口修正先通过实际失败构建复现 `node:net` 问题，修复后 contracts 构建、35 项 Web 用例、Web 生产构建通过；随后整仓 `pnpm build` 与 43 项 API 集成在最终代码上再次通过。未将这些定向验证描述为又执行了一遍完整单元套件。
